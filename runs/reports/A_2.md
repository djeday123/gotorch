# A-2 — buffer cache для тренировочных аллокаций (глава A, третий ход)

**Дата:** 2026-07-24
**Тип:** третий ход главы A-BRIDGE (после A-0 matmul-bwd и A-1 CE-fused). Одно звено — одна атака: устранить 6 больших allocs из hot loop.
**Результат:** speed **255.7× vs B2** (18.735 мс), **1.04× vs A-1**. Accuracy **PERFECT bit-exact** vs A-1 (worst |A-B| = 0.000e+00). CV резко улучшился 3.90% → 1.85%. User's прогноз "12 мс/33 мс alloc" не подтвердился — реальная выгода 0.6 мс, что совпадает с моей A-1 CPU-картой (alloc был 0.93 мс).

---

## 1. Инфраструктура

**Новый тип:** `BattleScratch` в `goml/internal/abjexam/battle.go`.

Struct с 6 pre-allocated буферами:
```go
type BattleScratch struct {
    Embedded   backend.Storage // F32 [m, Embed]  =  1 MB
    Normed     backend.Storage // F32 [m, Embed]  =  1 MB
    Logits     backend.Storage // F32 [m, Vocab]  =128 MB
    Loss       backend.Storage // F32 [m]         =  4 KB
    GradLogits backend.Storage // F32 [m, Vocab]  =128 MB
    GradOW     backend.Storage // F32 [Embed, V]  = 32 MB
    // Итого: ~290 MB
}
```

- **`NewBattleScratch(cfg, b)`** — одноразовый alloc всех 6 буферов.
- **`(*BattleScratch).FreeAll(b)`** — освобождает все, nil-safe.
- **Zero-fill semantics analysis (записано в комментарии struct):**
  - `embedded/normed/logits/loss/gradLogits` — каждый шаг полностью перезаписываются kernel'ами.
  - `gradOW` — `MatMulF32Ex` с `beta=0`. cuBLAS special-cases `beta=0` (не читает C, безопасно на любом контенте).
  - **Итог: НИ ОДИН буфер не требует per-step zero-fill.** MemsetD32Async binding не понадобился (у нас `cuMemsetD8` уже есть в goml — не использован).

**tokens/targets НЕ в scratch** — содержимое меняется каждый шаг, размер мал (12 KB), alloc-per-step приемлем. **Одно звено — одна атака** (правило пользователя).

**Новый Step:** `trainStepBattleA2(b, st, scratch, inp, tgt, step)` — идентичен `trainStepBattleA1`, кроме использования `scratch.*` вместо `b.Alloc(...)` для 6 буферов.

## 3. Speed — 30-run FA-класс

**Гейт:**
- nvidia-smi silence: util=0%, mem=12 MiB ✓
- Clocks до: 180 MHz idle / 32°C / 16.27 W
- Clocks после: 2685 MHz boost / 35°C / 120.65 W

| режим | median (ms) | CV (%) | vs B2 | vs A-1 |
|-------|-------------|--------|-------|--------|
| **A-2 buffer-cache** | **18.735** | **1.85** | **255.7×** | **1.04×** |

**Прогноз-vs-факт:**
- **Мой прогноз** (из A-1 CPU-карты, alloc 0.93 мс уходит): 19.7 − 0.93 = **~18.8 мс** → факт 18.735 = попал в 0.3%.

**CV резко улучшился 3.90% → 1.85%.**
Механизм: `Alloc/Free` были главным источником wall-jitter'а (Go GC, cuMemAlloc scheduling variance). Их устранение — не только -0.9 мс медианы, но и половинное CV. **Побочная победа A-2 больше формальной.**

> **A-2 buffer-cache:** accuracy **PERFECT bit-exact vs A-1** (0/8.2M grad diffs, 0 loss diffs на 50 шагах). Speed **255.7× vs B2** (18.735 мс vs 4791.5 мс), **1.04× vs A-1** — маргинально, ожидаемо (alloc был 0.93 мс из 19.7, устранение = -3%). **CV половинился** 3.90% → 1.85% — устранение allocs как источника wall-jitter'а.
>
> **Прогноз bit-exact подтверждён** (no hidden dependency on memory freshness). Zero-fill semantics analysis показал: НИ ОДИН из 6 буферов не требует per-step zero-fill (все ядра overwrite, cuBLAS beta=0 special-case работает). MemsetD32Async binding не понадобился.

**Главное открытие для главы A следующего хода:** gradOW D2H (12.7 мс = 66.6%) остаётся тестовым #1. Убрать в prod (A-3) = wall ~6.4 мс = **speedup ~750× vs B2**. ## 7. Фраза "фьюзинг платит точностью" (для A-1 архива)

Дополнение к A_1.md согласно решению пользователя:

Fused CE-kernel `cross_entropy_f32` устраняет один softmax-проход в composition path'е:
- **Naive path** (без fused): forward: `Softmax(logits) → probs` (3 passes) + host CE (from probs) → gradLogits scatter (from probs) = **4 passes** через vocab.
- **Fused path A-1**: max → sum_exp → grad+loss (все inline) = **3 passes** через vocab.
- **-1 pass = -N rounding steps на elements**, что снижает cumulative accum-error по правилу sqrt(N)·eps на количество избыточных проходов.

**"Фьюзинг платит точностью"** — это про меньшее число промежуточных материализаций (probs → host → back) и меньшее число зависимых округлений. В A-1 A/B thoughts: worst |A-B| loss = 5.31e-7, что в 3× ниже теоретического прогноза 1.5e-6 для 4-pass path'а. Fused = fewer rounding = tighter numerical envelope.
