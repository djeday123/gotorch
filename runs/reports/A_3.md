# A-3 — prod-Step без test-D2H (глава A, финал battle-цепочки)

**Дата:** 2026-07-25
**Тип:** финальный ход battle-цепочки. Форензика A-3.0 (обязательная до кода) + SGD-верификация A-3.1 + prod-Step A-3.2.
**Результат:** speed **772.2× vs B2** (6.205 мс vs 4791.5 мс), **3.02× vs A-2**. **CV впервые ниже 1% гейта** (0.27%). Прогноз 6-7мс попал в 0.005 мс. Battle-цепочка **объявляется закрытой**.

---

## 1. A-3.0 — Форензика (до любого кода)

### 1a. Правила зафиксированы в durable memory

- **[feedback-cv-gate-strict]** — CV > 1% в 30-run speed = число НЕ публикуется в прогрессию без разбора. GPU-bound wall < 20мс требует cudaEvent для sub-1% CV; уровень battle-прогрессии допускает 2-4% CV со сноской «условно-сертифицировано».
- **[feedback-cpumap-anomaly-verification]** — аномалия блока > 2× между сессиями = 2-й метод верификации до решений. Всегда указывать sum(blocks) vs wall convergence таблицей.

### 1b. Проверка "45 vs 19.5" (заявлено пользователем)

**Вердикт форензики (пост-факт, зафиксирован по решению пользователя):**
Форензика инициирована расхождением в **МОЁМ ревью A-1** (пересказ карты, которой не было — reconstruction error, не артефакт измерений). Rerun A-1 воспроизвёл 19.541/19.414 = 0.65% delta; прогрессия консистентна; sum(blocks)/wall = 99.96% сходимости. **Ложная тревога, породившая два верных durable-правила** (`feedback-cv-gate-strict`, `feedback-cpumap-anomaly-verification`) — правила остаются в силе независимо от повода рождения.

**Форензический факт:** ни числа "45 ms", ни "33 ms" в моих логах A-0/A-1/A-2 нет. Полная выборка всех speed-median из логов:

```
A-0 speed:  median 136.183 ms, CV 1.92%
A-1 speed:  median  19.414 ms, CV 3.90%
A-2 speed:  median  18.735 ms, CV 1.85%
B2 speed:   F32 4791.5 / F16 4804.5 / F8 4848.2 ms
```

**A-1 speed rerun (fresh session, A-3.0)**:
```
median 19.541 ms, CV 2.09%
```
Разница vs original A-1 = 0.13 ms (0.65%). **19.5 воспроизводится**. "45" — не существует в моих измерениях; возможно ghost-number или misreading.

### 1c. Sum(blocks) vs wall convergence — таблица

| session | Σ blocks (ms) | residual (ms) | total wall (ms) | Σ/total |
|---------|---------------|---------------|-----------------|---------|
| A-0 | 116.919 | 8.654 (alloc+free+Go) | 125.573 | 93.1% |
| A-1 | 18.779 | 0.934 (alloc+free) | 19.713 | 95.3% |
| A-2 | 19.042 | 0.027 (Go overhead) | 19.070 | **99.86%** |
| **A-3** | **6.228** | **0.002 (~zero)** | **6.230** | **99.96%** |

Residual честно снижается по мере устранения allocs. **Никаких скрытых источников измерения не обнаружено.** Моя A-1 карта (alloc = 0.934 мс) была точной; wall_A-1 → wall_A-2 = 19.7 → 19.07 = **-0.6 мс = ровно alloc** (полная согласованность с A-1 картой).

### 1d. A-1 CV formal violation — ретро-сноска

A-1 speed опубликован с CV 3.90% > 1% гейт. Мой пропуск. **Ретроспективная сноска для всей A-series:** A-1 число 19.414 ms — **условно-сертифицировано** (CV 3.90%, механизм: GPU-bound wall + host copies structural jitter, воспроизведён rerun 19.541 ms CV 2.09%). A-0 CV 1.92% также маргинально выше гейта. A-2 CV 1.85% то же. **A-3 первый честный** (CV 0.27%).

## 2. A-3.1 — SGD верификация (файл:строка)

**Вопрос:** где физически обновляются веса в battle-шаге?

**Ответ:** SGD (AdamW) полностью на GPU через PTX kernel:
- Kernel регистрация: `goml/backend/cuda/kernels.go:610` (`"adamw_f32"` в `kernelNames`).
- Kernel launch:
  - `battle.go:285` (trainStepBattle F32-baseline)
  - `battle.go:428` (trainStepBattleA0)
  - `battle.go:574` (trainStepBattleA1)
  - `battle.go:784` (trainStepBattleA2)
  - `battle.go:939` (trainStepBattleA3 — this doc)
- Состояние на GPU персистит: `OutW`, `OutMomM`, `OutMomV` в `BattleState`, никогда не спускается на host.

**Заключение:** SGD **уже на GPU**. Значит `gradOW D2H` в тестовых Step'ах — **чисто для сверки в A/B тестах** (host-side gradient comparison). В prod'е избыточен.

Статус **"gradOW D2H = test-only" подтверждён фактом кода**. A-3.2 = убрать этот D2H в prod-Step.

## 3. A-3.2 — Prod-Step без test-D2H

**Изменение:** новая функция `trainStepBattleA3(b, st, scratch, inp, tgt, step) → (loss float64, err error)`.
- Идентичен `trainStepBattleA2` кроме return: **НЕ спускает gradOW на host**.
- Возвращает только `loss` (per-row loss D2H 4 KB → host sum → /m).
- gradOW живёт на GPU, adamw_f32 напрямую читает device pointer.

### 3b. 30-run speed (FA-класс, CV-gate compliant)

- Silence gate: util=0%, mem=12 MiB ✓
- Clocks до: 180 MHz idle
- Clocks после: 2670 MHz boost, 35°C, 84.14 W

| режим | median (ms) | CV (%) | vs B2 (4791.5) | vs A-2 (18.735) |
|-------|-------------|--------|----------------|-----------------|
| **A-3 prod no-D2H** | **6.205** | **0.27** | **772.2×** | **3.02×** |

**CV 0.27% ниже 1% гейта** — первый honest publish без сноски. Механизм: убрали единственный крупный D2H copy (12.7 мс gradOW), остаток — GPU-side compute (более детерминистический wall).

**Прогноз "6-7 мс, speedup ~750×" попал в 0.005 мс.**

### 3c. CPU-MAP 4-я — новая композиция

| # | block | median (ms) | share |
|---|-------|-------------|-------|
| 1 | tokens+targets H2D | 0.015 | 0.2% |
| 2 | Embedding GPU | 0.009 | 0.1% |
| 3 | LayerNorm GPU | 0.030 | 0.5% |
| 4 | MatMul-fwd GPU | 0.292 | 4.7% |
| **5** | **cross_entropy_f32 GPU** | **5.507** | **88.4%** ← **новая доминанта** |
| 6 | MatMul-bwd GPU (F32Ex) | 0.263 | 4.2% |
| 7 | adamw_f32 GPU | 0.103 | 1.6% |
| 8 | loss[m] D2H (4 KB) | 0.010 | 0.2% |
| 9 | residual | 0.002 | 0.04% |
| **TOTAL** | | **6.230** | 100% |
| **Sum(blocks 1-8) / total** | | **99.96%** | (feedback-cpumap-anomaly-verification pass) |

**Финальная композиция battle-Step'а:**
- CE kernel **88.4%** (5.5 мс) — 1-thread-per-row sequential, warp-shuffle параллельная версия дала бы 3-5× kernel speedup. Но в battle-контексте это финал: 6→2 мс = ещё +3× wall. **Отложено в очередь nn.LLM stage** (по решению пользователя A-3.3): там CE будет ~10% wall'а при живом attention, актуальнее.
- MatMul fwd+bwd = 8.9% (0.55 мс сумма) — оптимально.
- adamw + LayerNorm + Embedding + loss D2H = 2.5% суммарно, оптимально.
- Alloc/Free residual **0.04%** = устранён.

## 4. Финальная прогрессия battle-цепочки (честная, с сносками)

| stage | median (ms) | CV (%) | speedup vs B2 | статус | сноска |
|-------|-------------|--------|---------------|--------|--------|
| **B2 F32 baseline** | 4791.5 | 1.87 | 1× | ✓ | CV условно |
| **A-0** matmul-bwd → GPU | 136.183 | 1.92 | **35.2×** | ✓ | CV условно |
| **A-1** fused CE kernel | 19.414 | 3.90 | **246.8×** | ✓ | **CV условно-сертифицировано** (rerun 19.541 CV 2.09% подтвердил, feedback-cv-gate-strict) |

**CE kernel не оптимизирован** (1-thread-per-row): parallel warp-shuffle версия → 6.2 → ~2 мс = ~2400× vs B2. Отложено.

## 6. Verdict

> **A-3 prod no-D2H:** accuracy **PERFECT bit-exact vs A-2** (0 loss diffs на 50 шагах). Speed **772.2× vs B2** (6.205 мс), **3.02× vs A-2**. **CV 0.27%** — **впервые ниже 1% гейта** без сноски. Прогноз 6-7 мс попал в 0.005 мс.
>
> **Battle-цепочка объявляется закрытой.** Финальная прогрессия B2 4791.5 → A-0 136.2 → A-1 19.4 → A-2 18.7 → **A-3 6.2** мс. CE kernel 88.4% wall'а осталось не тронутым (warp-shuffle отложено в nn.LLM stage per A-3.3). GPU compute 99.96% wall'а, alloc residual 0.04% (устранён).

**Инфраструктурные победы главы A:**
1. `MatMulF32Ex` через wrapper trans-flags (переносимо на любой linear-backward).
2. `cross_entropy_f32` PTX kernel (fused max→sum→loss+grad с in-kernel invM).
3. `BattleScratch` pattern (pre-alloc + zero-fill analysis, переносимо на любой Step со статичными формами).
4. Prod/test разделение путей (test-D2H vs prod без D2H) — паттерн для будущих Steps.
5. 3 новых durable feedback: sqrt(K)·eps (case 4 подтвердил), CV-gate-strict, cpumap-anomaly-verification.
