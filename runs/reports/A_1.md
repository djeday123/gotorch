# A-1 — fused CrossEntropy GPU-kernel (глава A, второй ход)

**Дата:** 2026-07-24
**Тип:** второй ход главы A-BRIDGE (после A-0 matmul-backward). Устраняет 81% wall'а A-0 картой (probs D2H + CE host + gradLogits H2D) через один fused kernel.
**Результат:** speed **246.8× vs B2 baseline** (19.4 мс vs 4791.5 мс), **7.02× vs A-0** (136 мс). Accuracy essentially bit-exact (loss diff 5.31e-7 при floor 1e-4). CPU-map показала новую узкую точку — gradOW D2H (63% wall'а, но prod-избыточен).

---

## 1. Инфраструктура

**Новый kernel:** `cross_entropy_f32` в `goml/backend/cuda/kernels_b.go`.

Signature (PTX):
```
cross_entropy_f32(
    logits    [num_rows, vocab] F32,
    targets   [num_rows]        int32 (upload as u32-compat),
    loss_out  [num_rows]        F32   per-row NLL (не масштабировано)
    grad_out  [num_rows, vocab] F32   (softmax - onehot) * inv_bs
    p_inv_bs  F32
)
```

- **Двухпроходная схема** (max → sum → grad + loss).  Обоснование: корректность первична (user: "производительность вторична"). Три sequential прохода по строке vocab=32000 на 1 thread/row (тот же паттерн что `softmax_f32`).
- **Numerically stable softmax в log-домене**: `log_z = max + log(sum(exp(logits - max)))`.
- **log/exp через PTX intrinsics**: `lg2.approx.f32`, `ex2.approx.f32`, `rcp.approx.f32` (1-3 ULP).
- **Никаких probs materializаций в host**: единственный host копия — `loss[m]` (m*4=4 KB для скалярного loss на лог).
- Registered в `kernelNames_B` array.

**Новый Step:** `trainStepBattleA1` в `internal/abjexam/battle.go`. Отличие от `trainStepBattleA0`: убраны Softmax + probs D2H + CE host + gradLogits H2D → один `Launch("cross_entropy_f32", ...)`. Всё остальное (MatMulF32Ex bwd, AdamW) от A-0.

## 2. Дисциплина PTX JIT (feedback-ptx-jit-log-diagnostic сработал)

Первый прогон accuracy quick вернул `cuModuleLoadData (PTX Phase B): CUDA_ERROR(218)` (INVALID_PTX). Ptxas 11.5 (offline, /usr/bin) accepted, но driver 580 (CUDA 12.8 JIT) rejected.

Разбор через ptxas 12.8:
```
ptxas fatal   : Unexpected non-ASCII character encountered on line 723
```

**Механизм:** Unicode `≥` и кириллица в комментариях моего PTX. Ptxas 11.5 permissive, 12+ строгий (только ASCII в комментариях). Fix — ASCII-only комментарии, повторный extract+ptxas 12.8 PASS.

**Уроки для feedback-ptx-jit-log-diagnostic:**
- Ptxas старой версии НЕ надёжный test — cross-check с ptxas новой версии обязателен для новых PTX-модулей.
- Driver JIT ≠ offline ptxas того же поколения.

## 5. Speed — 30-run FA-класс + Амдал-арифметика прогноза

**Гейт запуска:**
- nvidia-smi silence: util=0%, mem=12 MiB ✓
- Clocks до: 180 MHz idle / 32°C / 16.10 W
- Clocks после: 2707 MHz boost / 34°C / 120.59 W

**Результат:**

| режим | median (ms) | CV (%) | speedup vs B2 (4791.5 ms) | speedup vs A-0 (136.2 ms) |
|-------|-------------|--------|----------------------------|---------------------------|
| **A-1 CE-fused** | **19.414** | **3.90** | **246.8×** | **7.02×** |

**Прогноз (арифметика из CPU-карты A-0):**
```
125.6 ms (A-0 total)
  minus probs D2H              49.24 ms  ←  устранено CE-scatter
  minus CE host build          21.24 ms  ←  устранено
  minus gradLogits H2D         31.40 ms  ←  устранено
  plus  CE kernel (est ~1 ms)  +1.00 ms
  =                             25.00 ms (прогноз)
```

**Реальность 19.41 мс — на 5.6 мс лучше прогноза** (речевая расшифровка: alloc overhead и gradOW D2H в A-1 несколько меньше из-за WARM caches, targets int32 upload 4 KB тривиален, CE kernel 5.5 мс vs прогноз 1 мс). Прогноз попал в 22% от факта — на 5× точнее чем в A-0.

**CV 3.90% > 1% — разбор:**
- Wall теперь 19 мс, per-step jitter ±0.8 мс → 4%.
- Механизм: GPU-bound wall, jitter от launch overhead + Sync barrier + kernel completion.
- CV структурный, не publishing-issue: разбор в отчёт, не подавляем.
- Для sub-1% CV нужен GPU-timing без Go-runtime interference — cudaEvent + stream capture. Вне scope A-1.

**Speedup 246.8× при прогнозе 190× — прогноз побит на 30%**. Модель "устраняем 3 куска" сработала точнее чем в A-0 (там 300× → 35× miss 10×). Причина: реальные значения устранённых кусков (49+21+31=101 мс) хорошо совпали с картой, а CE kernel add-on минимален (5.5 мс vs ожидание 1-2 мс).

## 6. Новая CPU-MAP — 10 блоков `trainStepBattleA1`

Инструментированный прогон, per-block Sync-граница, medians 10 iter.

| # | block | median (ms) | share | сравнение A-0 |
|---|-------|-------------|-------|---------------|
| 1 | tokens+targets H2D | 0.040 | 0.2% | было 0.03 (растёт: +targets int32 upload) |
| 2 | Embedding GPU | 0.023 | 0.1% | == |
| 3 | LayerNorm GPU | 0.032 | 0.2% | == |
| 4 | MatMul-fwd GPU | 0.326 | 1.7% | == |
| **5** | **cross_entropy_f32 GPU** | **5.503** | **27.9%** | **NEW** (заменил 3 куска = 101.9 мс) |
| 6 | MatMul-bwd GPU (F32Ex) | 0.314 | 1.6% | == |
| 7 | adamw_f32 GPU | 0.105 | 0.5% | == |
| 8 | loss[m] D2H (4 KB) | 0.015 | 0.1% | == заменило 128 MB copies |
| **9** | **gradOW D2H (32 MB, ТОЛЬКО для сверки в тесте)** | **12.421** | **63.0%** | **new #1** (было 11% share, wall тот же) |
| 10 | alloc+free overhead | 0.934 | 4.7% | было 6.9% (в 10× меньше wall) |
| — | **TOTAL** | **19.713** | 100% | vs A-0 125.6 мс = **6.37× reduction** |

**Ключевая находка** — **gradOW D2H 12.4 мс (63% wall'а) присутствует ТОЛЬКО потому что тест сверяет grad с host-версией**. В production Step он **избыточен** (adamw обновляет OutW прямо на GPU без host round-trip).

**Если убрать gradOW D2H return path в prod:**
- wall = 19.4 − 12.4 = **~7 мс**
- speedup vs B2 = **~685×**

**Второй кандидат** после этого — сам CE kernel 5.5 мс (28%). Параллельный warp-shuffle reduction resect 3-5×, wall упал бы ещё на ~4 мс → **~3 мс** → **~1600×**. Но это уже требует переписки kernel'а на параллельный (не 1-thread-per-row как сейчас).

## 8. Verdict

> **A-1 CE-fused:** accuracy **essentially bit-exact vs A-0** (loss diff 5.31e-7 внутри floor 1e-4 = запас 188×; grad hybridFail 0/8.2M). Speed **246.8× vs B2** (19.4 мс vs 4791.5 мс) и **7.02× vs A-0** — прогноз 190× побит на 30%. Memory ~similar (fused kernel не добавляет буферов).
>
> **Три куска устранены одним kernel'ом**: probs D2H 49 мс + CE host 21 мс + gradLogits H2D 31 мс = 101 мс = 81% wall'а A-0. Add-on CE kernel 5.5 мс. Netto minus 96 мс.
>
> **sqrt(V)·eps модель приложима**: V=32000 → prognosis 1.07e-5, actual battle 8.95e-6 (в теоретическом пределе, 25% ниже). Четвёртый case durable правила (impl-3 / B-impl-1 / A-0 / A-1).

**Главное открытие для главы A следующего хода:** GPU compute поднялся с 1% (A-0) до 30% wall'а (A-1). Один D2H copy (gradOW 12 мс) держит 63% — **тривиальный fix (убрать return path в prod)** даёт ещё ×2 speedup → ~685×. Attention всё ещё не следующая цель — сначала D2H cleanup + возможно параллельный CE kernel.

## 10. Решения перед A-2 (для пользователя)

**Р1.** Убрать `gradOW D2H` return path из prod `trainStepBattleA1` (оставить в тесте A/B). Тривиально: одна условная строка. Free ~12 мс = **speedup 685× vs B2**. Это ещё pre-attention ход.

**Р2.** Параллельный warp-shuffle reduction для `cross_entropy_f32` (сейчас 1-thread-per-row sequential, 5.5 мс на V=32000). Ожидание 3-5× ускорение kernel → 1-2 мс → wall ~15 мс без Р1, ~4 мс с Р1. Небольшая переписка PTX. Может быть A-3.

**Р3.** Attention forward+backward через FA-ядра (первоначальная цель главы A) — после Р1 и Р2 GPU compute становится ~1 мс на шаг, attention добавит ~50 мс fused-bwd → attention станет 90%+ wall'а. Тогда стрелка на attention начнёт покупать реальный speedup. До этого — не давит.

**Р4.** Alloc-overhead 0.93 мс (5%) — user попросил не трогать в A-1 ("одно звено — одна атака"). После Р1 + Р2 alloc может подняться до 20-30% — тогда pre-allocate имеет смысл. Р4 candidate = post-Р2.

**Р5. FA-canary counter 2/3 OUT-вверх** — следующий any-glava запуск даст 3-й OUT → **обязательный re-anchor** через 5-run canary session (по протоколу пользователя).

**СТОП.** Ждём ревью и решения по А-2 (рекомендация: Р1 = убрать gradOW D2H — тривиально + ×2 speedup за 1 строку).
